## 记录原则

开发范围为 TileLang 主仓；服务端所有写入限定在 `/home/f00959234/yjl`。每轮先通过正确性检查，再记录设备事件和独立 profiling 的内核时间。输入采用固定种子并核对完整 SHA-256。不同输入、shape 或计时口径的数据不混算加速比。

本地最初没有 `.git`；从当前文件快照建立版本库，不声称恢复了原项目历史。Git 短哈希通过下表标签解析，避免在提交内容中递归嵌入自身哈希。大型原始证据保留在 `artifacts`，不纳入 Git。

主仓中可变 SIMD 直方图寄存器、uint16→uint32 扩展与累计桶边界已由 950PR 最小实验验证。通用 `popcount`、`shfl_sync` 在当前主仓降低路径中不可直接使用；`warp_reduce_sum` 可运行，实际组宽为 32。以上是本环境实测能力，不外推到其他提交或工具链版本。

`v0.1.1` 提交中保存的最小代码改动是：剩余配额已经为零时，跳过最终同分扫描。它的两组完整 Prefill 一快一慢，没有确立整体收益。Decode 完整轮的 profiling 与事件时间差异显著，原始数据保留，不将异常采样用作可靠内核加速比。该版本标记为 experimental，不能当作最佳实现。

该轮完整原始采样见 [v0.1.1](../performance/topk-select-950pr/v0.1.1.json)。原始字节 SHA 与 Git 入库换行归一后的 SHA 分别记录，避免将 CRLF/LF 变化误判为不可追溯源码。

## 优化顺序

第三轮首次完整测试曾在连续运行中异常耗费 CPU；同一用例独立运行通过，增加单项 180 秒超时后，完整 14 项在 237.93 秒通过。不能据此判定是确定的编译器缺陷。UB 缓存正确性通过不代表高效，实测回退也不能仅凭猜测归因于 UB 银行冲突或同步；尚未做指令级消融。该版本显式 UB 最大约 97.5 KiB，不包含编译临时空间。

1. 直方图与桶扫描：先检查主仓对 SIMD 统计和扫描的实际表达能力，按可用能力做最小实现和实测。
2. FP16 粗桶、FP32 精确细化：验证完整输入域的顺序规则，保留候选溢出重扫与同分索引确定性。
3. UB 分块搬运：分别核实批量搬运与计算收益，不把候选 ping-pong 当成输入流水。
4. 调度：分别评估 Prefill worker 数和 Decode 行内并行。

每轮保存独立提交及标签。若正确性失败或性能回退，记录失败原因，并恢复最佳已验证实现；不将回退实验伪装为有效优化。
